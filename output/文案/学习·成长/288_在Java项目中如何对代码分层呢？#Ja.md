哈喽，在 Java 项目中，如何对代码进行分层呢？一般来说会有我们的一个Controller、 Service 以及 Mapper 三层架构。 Mapper 是我们去写 SQL 和数据库进行交互的一个持久化层。 Service 业务层去写我们的一个业务逻辑。 Controller 视图层去暴露我们的一个 API 接口。这里来简单说一下我发现的几个小问题吧。

Speaker 1 00:00:20.970 
第一个问题是我们的一个 Controller 层里面，很多小伙伴喜欢去写我们的一个业务逻辑到我们的一个 Controller 里面，这样的话就会导致我们的一个 Controller 层就代码很臃肿。合理的情况下应该是将我们的一个业务代码，写到我们一个 Service 里面去。再由我们一个 Controller 层里面去调用我们 Service 里面方法，这样的话我们的一个代码就看上去比较清爽。

Speaker 1 00:00:42.040 
第二个问题是我们的一个Mapper，很多小伙伴会将我们的一个 Mapper 就放到我们各个地方去调用使用。比如说我们新增一个商品的接口，可能同事之间你看我代码不爽，我看你代码不爽，你想写一套，我也想写一套，这样的话会导致我们的一个入口不统一。出问题排查的时候就不好排查。合理的情况下，比如说我这里是写一个商品的一个map，那我这个商品的 map 就只能交给我，就商品的一个 service 里面去进行我们的一个调用，这样的话就形成了我们的一个闭合。

Speaker 1 00:01:15.950 
第三个问题是我们的一个 service 的一个主次关系，比如说我这里有个商品 SPU 和我们的一个商品规格SKU，商品属于我们的一个主，然后 SKU 是属于我们的一个次，很多小伙伴就。喜欢在我们的一个 SPU 里面去调SKU，再到我们一个 SKU 里面去调我们的一个SPU，这样的话就会导致我们很容易去产生我们的一个循环依赖。合理的情况下应该是在我们的商品里面去调用我们的一个规格service，规格 service 里面就只能去写我们的一个规格相关的一个业务了，这样的话我们的一个 service 里面的这些病就不会太多。最后你们有什么更好的见解吗？可以评论分享一下，谢谢。
